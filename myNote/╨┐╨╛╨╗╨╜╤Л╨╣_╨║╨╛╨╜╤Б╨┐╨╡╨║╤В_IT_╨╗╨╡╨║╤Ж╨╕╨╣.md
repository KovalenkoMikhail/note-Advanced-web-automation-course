## 9. Веб-автоматизация и локаторы

### XPath локаторы

#### Основные операторы и оси:

- **`/`** - прямой потомок
- **`//`** - любой потомок
- **`.`** - текущий элемент
- **`..`** - родительский элемент
- **`@`** - атрибут элемента

#### Фильтры:

- **`[]`** - для фильтрации
- **Пример:** `//div[@class = 'ticket']`

#### Функции XPath:

- **`text()`** - используется внутри элемента
- **`contains()`** - содержит
- **`starts-with()`** - начинается с
- **`ends-with()`** - заканчивается на
- **`position()`** - позиция

#### Логические операторы:

- **`and, or`** - для комбинированных условий
- **Пример:** `//a[@class = 'link' and contains(text(), 'example')]`

### Примеры XPath локаторов:

#### По атрибутам:

- **`//*[@id='username']`** - по ID
- **`//*[@class='passwords']`** - по имени класса
- **`//*[@name='pass']`** - по имени
- **`//p`** - по имени тега

#### По тексту:

- **`//*[text()='Submit']`** - по тексту

#### С использованием функций:

- **`//*[contains(@href, 'google.com')]`** - использовать Contains
- **`//*[starts-with(@id, 'user')]`** - в начале
- **`//*[ends-with(@id, 'name')]`** - в конце

### CSS селекторы:

#### Основные селекторы:

- **`#my-id`** - по ID
- **`.my-class`** - по классу
- **`[name='q']`** - по атрибуту
- **`button[type='submit']`** - по тегу и атрибуту

### Разница между статическим и динамическим путем:

#### Статический путь:

- **`html/body/div[1]/div[2]`** - жестко привязан к структуре

#### Динамический путь:

- **`//input[contains(@id,'user')]`** - более гибкий поиск

### Общий синтаксис XPath:

**`Путь = // имя_тега [@атрибут = 'значение']`**

#### Примеры:

- **`//input[@id = 'username']`** - по имени тега
- **`//button[contains(@class, 'Submit')]`** - использование contains()
- **`//input[starts-with(@name, 'email')]`** - использование starts-with()
- **`//input[@id='password']/preceding-sibling::label`** - использование preceding-sibling

## 10. Telegram Bot API

### Взаимодействие с пользователем

**Telegram бот взаимодействует с пользователем через Telegram API**

### Механизмы получения сообщений:

#### Long Polling:

- **Бот запрашивает "Есть новые сообщения?"** - просто, но неэффективно

#### Webhook:

- **Бот дает Telegram URL-адрес** - на который Telegram сам отправляет сообщения

### Подключение к API:

1. **Создать бота-сервис в Telegram** (через Bot Father)
2. **Получить токен** (от Bot Father)
3. **Запрос к API должен содержать токен**
4. **Токен проставляется в конфигурациях**

### Особенности работы:

- **Как и в обычном REST API** - в боте сохраняются состояния
- **Важно тестировать полные пути** - учитывая сохранение состояний

## 12. Дополнительные HTTP методы

### HTTP методы:

#### OPTIONS:

- **Запрос метаданных о ресурсе** - для получения информации о том, какие методы обрабатывает ресурс

## 13. Хранение данных в браузере

### Сравнение механизмов хранения:

| Характеристика   | Cookie                                           | Local Storage                                                                              | Session Storage                           |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------ | ----------------------------------------- |
| **Срок жизни**   | Устанавливается сервером                         | Сохраняются, пока пользователь их не почистит вручную                                      | Действуют до закрытия вкладки браузера    |
| **Доступ**       | Доступны для клиента (браузера) и сервера        | Только для клиента (браузера)                                                              | Только для клиента (браузера)             |
| **Объем данных** | 2-5 КБ                                           | 5-10 МБ                                                                                    | Временное хранение                        |
| **Назначение**   | Аутентификация, персонализация, отслеживание     | Хранение данных, которые должны сохраняться долгое время (например, режим темы интерфейса) | Временное хранение данных                 |
| **Безопасность** | Уязвимости для CSRF (Cross-Site Request Forgery) | Уязвимости для XSS (Cross-Site Scripting)                                                  | Уязвимости для XSS (Cross-Site Scripting) |
| **Пример**       | Токен сессии                                     | Настройка интерфейса                                                                       | Заполненная форма перед отправкой         |
