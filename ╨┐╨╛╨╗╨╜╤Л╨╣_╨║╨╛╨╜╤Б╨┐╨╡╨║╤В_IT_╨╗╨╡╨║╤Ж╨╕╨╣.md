# Полный конспект IT лекций

## 1. DNS (Domain Name System) - Система доменных имен

### Основные понятия

**DNS** - как телефонный справочник, преобразует человекочитаемые доменные имена (например, google.com) в IP-адреса (например, 172.217.160.142).

### Процесс разрешения DNS-запросов

#### Уровни кэширования:

1. **Локальный кэш DNS Resolver Cache** - хранится в операционной системе
2. **Кэш роутера (маршрутизатора)**
3. **DNS-сервер провайдера (ISP DNS Server)**
4. **Рекурсивный DNS-сервер** (если НЕ провайдер) - сторонние DNS-сервера вместо провайдера

#### Иерархия DNS-серверов:

- **Root DNS Servers** (Корневые DNS-серверы) - 13 групп серверов (от A до M)
- **TLD - Top-Level Domain** (Домен верхнего уровня) - .com, .org, .net
- **Authoritative DNS servers** (Авторитарные DNS-серверы) - хранят реальные IP адреса домена

### Кэширование DNS

- Рекурсивный DNS-сервер кэширует ответ
- Роутер кэширует
- Операционная система кэширует

### Смена IP-адреса

При смене IP-адреса:

- Держат открытыми старую и новую версии
- Минимум 24-48 часов, чтобы учесть максимальный TTL (Time To Live - время хранения кэша в DNS)
- Пользователи постепенно переходят на новый IP по мере обновления DNS кэша

### Типы DNS записей

- **A-record** - связывает доменное имя с IPv4-адресом (например, example.com → 192.0.1.1)
- **AAAA-Record** - для IPv6 (например, 2001:0db8:1)
- **CNAME-record** - псевдоним (например, www.example.com → example.com)
- **MX-Mail Exchange Record** - указывает сервер для получения почты (mail.example.com)
- **NS-record (Name Server)** - указывает DNS-сервер, являющийся авторитарным для доменов

### Инструменты для работы с DNS

- **nslookup google.com** - базовая команда для DNS-запросов
- **dig google.com** - более мощная альтернатива для DNS-запросов

#### Мониторинг систем

- Рост числа зависших транзакций

### Анализ и поиск в логах

- **Анализ трендов:** Регулярный просмотр метрик выявляет регрессии производительности
- **Бизнес метрики:** помогают отследить влияние производительности на пользовательский опыт (user experience)

## 3. Сетевые протоколы

### TCP (Transmission Control Protocol)

- **Надежный** - гарантирует доставку пакетов в правильном порядке без потерь
- **Медленнее чем UDP**
- **Three-way handshake** - для установления соединения
- **Flow control** - управляет скоростью отправки данных, чтобы не перегружать получателя
- **Congestion Control** - адаптируется к загруженности сети, чтобы не перегружать
- **Retransmission** - повторная отправка при потере пакета

#### Примеры использования TCP:

- **Веб HTTPS** - полная загрузка страниц
- **Передача файлов FTP**
- **Почта SMTP, POP3, IMAP**

### UDP (User Datagram Protocol)

- **Ненадежный** - не гарантирует доставку
- **Быстрый** - отсутствие проверок и подтверждений делает быстрее
- **Без соединения (Connectionless)**
- **Low Overhead** - меньше технической информации

#### Применение UDP:

- **Онлайн игры**
- **Voice chat** (голосовой чат)
- **Видеостриминг**

### QUIC (Quick UDP Internet Connection)

- **Новый транспортный протокол от Google** поверх UDP
- **Быстрое соединение** - объединяет TCP и TLS в одно
- **Может передавать несколько потоков** избегая Head-of-Line Blocking, как в TCP
- **Если пакет застрял - не блокирует потоки**
- **Устойчивость к смене сети** - имеет уникальный ID, поддерживает соединение даже при смене IP на телефоне
- **Встроенное TLS шифрование** (+ transport layer security)

## 4. Тестирование программного обеспечения

### Автоматизированные тесты для калькулятора

Проект написан на **Java (21)**, использует **JUnit 5** для тестирования, сборка через **Maven**.

### EchoCommandExecutor.java

Центральный класс, отвечает за выполнение математических выражений. Использует **ProcessBuilder** для запуска команд `sh -c 'echo ...'`.

#### ProcessBuilder - детали работы:

1. **ProcessBuilder** позволяет запустить отдельный процесс в терминале для выполнения всех вычислений и возврата в стандартный вывод
2. Использует `scale = 4` для форматирования до 4 знаков после запятой
3. Перехватывает вывод (`getInputStream`) для получения результатов и `getErrorStream` для получения сообщений об ошибках
4. Обрабатывает возможные таймауты и парсит вывод, чтобы убедиться, что это число

### Структура тестов JUnit 5

#### Аннотации:

- **`@Test`** - Аннотация JUnit 5. Помечает метод как тестовый
- **`@DisplayName`** - Человекочитаемое имя для тестового метода. Информативное
- **`@BeforeEach`** - инициализация перед каждым тестом
- **`@ParameterizedTest`** - позволяет запустить один и тот же тест несколько раз, но с разными наборами входных данных (аргументов)
- **`@MethodSource`** - для указания, что аргументы для теста вынесены в статический метод

#### Позитивные тесты

- **`@assertEquals`** - сравнение ожидаемого и фактического результата
- Проверяют корректную работу с валидными данными

#### Негативные тесты

- **`assertThrows`** - проверка выброса исключения
- **`assertTrue(getMessage().contains)`** - валидация текста ошибки
- Проверяют обработку некорректного ввода:
  - Деление на 0
  - Неверный формат
- Выбрасывают исключения, убеждаются, что не просто падает, а выдает ошибку, проверяют ее

### Обработка исключений

#### Try-catch блок

- **`try:`** - блок кода, где могут быть исключения
- Если происходит исключение - переход в блок `catch`

#### Типы исключений:

- **`NumberFormatException`** - при попытке преобразовать нечисловое значение
- **`IllegalArgumentException`** - тип исключения (Unchecked Exception). Выбрасывается когда метод получил недопустимый или неподходящий аргумент

#### `throw` - для явного выбрасывания исключения

Используется, когда код обнаруживает ошибку, которую не может обработать, и передает выше по стеку вызовов.

## 5. Java программирование

### ProcessBuilder и работа с процессами

#### Основные методы:

- **`getInputStream()`** - метод объекта Process, который возвращает поток данных со стандартного вывода
- **`getErrorStream()`** - для получения сообщений об ошибках
- **`waitFor()`** - убивает процесс, чтобы не висел
- **`Collectors.joining(System.lineSeparator())`** - статический метод из Java Stream API собирает элементы потока в одну большую строку используя разделитель

### Обработка строк

- **`trim()`** - метод класса String удаляет пробелы, табы и переводы строк с начала и конца строки
- **Конкатенация** - объединение строк

### Блок конвертации и форматирования

Этот блок пытается преобразовать текстовый вывод в число с плавающей точкой и форматирует его до четырех знаков после запятой, перехватывая ошибки, если вывод не является числом.

**Зачем?** При некоторых ошибках вывод идет не в error (stderr), а stdout (при делении на 0), поэтому нужно обрабатывать отдельно.

### Валидация и обработка ошибок:

1. Проверка `stderr` на наличие ошибок, если есть - выбрасывает `IllegalArgumentException`
2. Затем проверяет `stdout`, пустой вывод
3. `try-catch Double.parseDouble` - конвертация в число
4. Обработка `NumberFormatException`
5. Форматирование результата до 4 знаков после запятой

## 6. HTTP протоколы

### HTTP/1

- **Отсутствие приоритезации**
- **Браузер устанавливает несколько TCP соединений** (до 6)
- **Head of Line Blocking** - запрос подвис, заблочило поток

### HTTP/2

- **Multiplexing** - 1 TCP для всех запросов
- **Head of Line Blocking - pain point** - всё еще работает поверх TCP. 1 запрос подвис - блокируя поток
- **Stream Multiplexing** - один TCP для множественных запросов

### HTTP/3

- **UDP (QUIC)** и QUIC соединение для множественных потоков мультиплексирования
- **Stream Multiplexing**
- **Head of Line Blocking** - отсутствует
- **QUIC (1-RTT) + TLS встроенный, 0-RTT для возобновленного соединения**

### Сравнение протоколов

| Характеристика            | TCP       | HTTP/1.1                               | HTTP/2                                     | HTTP/3                        |
| ------------------------- | --------- | -------------------------------------- | ------------------------------------------ | ----------------------------- |
| **Соединения**            | 1 connect | Последовательно                        | Одно соединение для множественных запросов | UDP (QUIC)                    |
| **Parallelism**           | -         | Ограниченный, требует много соединений | Stream Multiplexing                        | Stream Multiplexing           |
| **Head of Line Blocking** | -         | Да                                     | Да (pain point)                            | Нет                           |
| **Handshake**             | TCP 3way  | TCP 3way + TLS/2 RTT                   | TCP 3way + TLS/2 RTT                       | QUIC (1-RTT) + TLS встроенный |
| **Request**               | Нет       | Нет                                    | Да                                         | Да                            |
| **Priority**              | Да        | Нет                                    | Да                                         | Да                            |
| **Server Push**           | Нет       | Нет                                    | Да                                         | Да                            |
| **Headers Compression**   | Да        | Да                                     | Да                                         | Да                            |

### HTTP заголовки и куки

#### Заголовки запроса (Request Headers):

- **User-Agent** - пользовательский агент
- **Content-Type** - тип содержимого
- **Authorization** - авторизация

#### Заголовки ответа (Response Headers):

- **Content-Type** - тип содержимого
- **Set-Cookie** - установить куки
- **Cache-Control** - управление кэшем

#### Куки (Cookies):

- **Небольшие фрагменты данных** для запоминания состояния клиента (сессии)

### Приоритизация запросов HTTP/3 и QUIC

#### Приоритеты запросов QUIC HTTP/3:

- **HTTP/3 в QUIC отсутствует Head-of-Line Blocking**
- **Каждый блок потока независим** - потеря пакета в одном потоке не влияет на другие
- **Client передает в header:**
  - **urgency: от 0 до 7** (высший Priority)

#### Best practice Priority:

**HTML, CSS:**

- urgency = 0, incremental = false

**Шрифты:**

- urgency = 1, incremental = false

**JavaScript:**

- Если скрипт блокирует рендер: urgency = 2/3
- Не блокирует: urgency = 0

**Изображения:**

- Видимой части: urgency = 3
- Below the fold: urgency = 4/5
- Для below the fold можно использовать incremental = true

### Dependencies & Weights (HTTP/2)

- **Зависимость выстраивают иерархию (Дерево)**
- **Style.css зависит от index.html** - получается после html отдаст CSS
- **Weights: присваивания от 1 до 256** - определено какой bandwidth получают относительно других ресурсов

## 7. Git - Система контроля версий

### Базовые команды Git

#### Инициализация и клонирование:

- **`git init`** - инициализация репозитория
- **`git clone <url>`** - клонирование репозитория
- **`git status`** - проверка статуса
- **`git log`** - просмотр истории коммитов

#### Работа с изменениями:

- **`git add .`** - добавление изменений
- **`git commit -m "message"`** - создание коммита
- **`git stash`** - временно сохранить незафиксированные изменения (покинуть)
- **`git stash pop`** - стянуть со Stash
- **Stash хранит локально** в .git

#### Работа с ветками (Branches):

- **`git branch:`** - посмотреть ветки
- **`git branch <имя>`** - создать branch
- **`git checkout <name>`** - переключиться на ветку
- **`git checkout -b <name>`** - создать и перейти
- **`git merge <name>`** - слияние веток
- **`git branch -d <name>`** - удалить ветку

### Работа с удаленными репозиториями

#### Команды для работы с репозиториями:

- **`git remote -v`** - список репозиториев
- **`git push origin <name>`** - отправить изменения в удаленный репозиторий

#### Получение изменений:

- **`git pull`** - скачать и объединить
- **`git fetch`** - скачать, не объединяет

#### Работа с коммитами и историей:

- **`git commit --amend`** - перезаписать предыдущий коммит
- **`git rebase`** - перезаписывает историю, переносит коммиты поверх основной ветки
- **`git merge`** - создает новый commit, в котором объединяет код, сохраняет историю

### Git Flow

#### Основные ветки:

- **`main`** - стабильна, готова к релизу
- **`develop`** - для интеграций новых фич
- **`feature`** - для разработки новых функций (от ветки develop)
- **`release`** - подготовка к релизу, стягивается с develop и пушится в main

#### Hotfix (срочное исправление):

- **hotfix** - для быстрых фиксов стягивается и пушится в main (простой Flow)

#### Best Flow hotfix:

1. **Создать ветку hotfix от main**
2. **Исправления и PR в main**
3. **Тестирование в main**
4. **Cherry-pick в релиз (Release/5)**

### Detached HEAD

- **Detached HEAD: Состояние, когда** текущий коммит указывает на сам commit, а не на ветку
- **Пример:** (при git checkout <ID commit>)
- **Для фикса - перейти на ветку**

### Поиск ошибок и отладка

#### git bisect:

- **`git bisect`** - помогает найти багу в коммитах путем разбиения диапазона пополам
- **`git bisect start`** - начало процесса
- **`git bisect good [ID commit]`** - где точно не было бага
- **← bad [ID коммита]** указывает commit где точно есть бага

#### git cherry-pick:

- **`git cherry-pick [ID commit]`** - изменения с одного коммита в другой, как будто были сделаны в main

### Теги и хуки

#### Tags (Теги):

- **Нужны для версий релизов** и указаний важных моментов
- **Содержат метаданные:** email, имя автора тега, дата
- **Пример:** `git tag -a v.1.0.0 -m "initials"` - создание аннотированного тега версии 1.0.0
- **stable release** - стабильный релиз

#### Hooks (хуки):

- **Запускаемые скрипты**

##### Типы хуков:

- **pre-commit** - проверка форматирования кода, линтинга, запуск Unit tests
- **prepare-commit-msg** - после ввода сообщения коммита файла
- **commit-msg** - обработка сообщения коммита
- **pre-push** - перед пушем
- **post-receive** - на репозитории после Push (для автоматической)

## 8. Performance Testing (Нагрузочное тестирование)

### Типы тестирования производительности

#### Load Testing:

- **Тестирование работы при ожидаемой нагрузке**

#### Stress Test:

- **Под нагрузкой** - цель: найти breaking point (точку отказа)

#### Spike Test:

- **Резкий рост трафика** (черная пятница)

#### Soak Testing (Endurance):

- **Длительное тестирование под ожидаемой нагрузкой**
- **Цель:** найти утечки памяти и другие проблемы

### Метрики производительности

- **Response time / Latency** - время ответа сервера
- **Throughput (пропускная способность)** - количество запросов в секунду/мин (TPS - Transaction per Second)
- **CPU / Memory Usage** - критично для выявления bottlenecks
- **Error Rate** - процент ошибок под нагрузкой

### Инструменты

- **JMeter, Gatling, LoadRunner**

### JMeter - детальное описание

#### Основные компоненты:

- **Test Plan** - хранит структуру теста
- **Thread Group** - виртуальные users, настраивай
  - **Number of threads (users)** - количество пользователей
  - **Ramp-up period** - если 100 юзеров и Ramp up в сек - каждые 0,1 сек будет новый юзер
  - **Loop Count** - сколько юзеров сделает действий (кейс)
- **Sampler** - действия (кейс) выполняемый пользователем
- **Listener** - собирает результаты тестов

#### Отчеты JMeter:

##### Summary Report:

- **# Samples** - общее количество запросов
- **Average** - среднее время отклика
- **Min/Max** - время отклика
- **Error%** - процент ошибок
- **Throughput** - количество запросов в секунду
- **Received/Sent** - полученные и отправленные данные

##### Aggregate Report:

- **Показывают время отклика** в которое уложились 90% всех запросов
- **Вне оценки стабильности** 95/99%

##### Graph Results:

- **Для визуализации графика** нагрузочной системы
- **JMeter загружает систему, лучше с консоли**
- **Отчет в виде файла**

#### Команды JMeter:

- **`jmeter -n -t my_test.jmx -l results.jtl`**
  - **`-n`** - запуск без UI
