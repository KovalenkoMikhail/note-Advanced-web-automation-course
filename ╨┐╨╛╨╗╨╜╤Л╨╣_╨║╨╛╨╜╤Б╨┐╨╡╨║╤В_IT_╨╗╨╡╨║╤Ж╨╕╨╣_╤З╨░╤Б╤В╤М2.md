## 9. Веб-автоматизация и локаторы

### XPath локаторы

#### Основные операторы и оси:

- **`/`** - прямой потомок
- **`//`** - любой потомок
- **`.`** - текущий элемент
- **`..`** - родительский элемент
- **`@`** - атрибут элемента

#### Фильтры:

- **`[]`** - для фильтрации
- **Пример:** `//div[@class = 'ticket']`

#### Функции XPath:

- **`text()`** - используется внутри элемента
- **`contains()`** - содержит
- **`starts-with()`** - начинается с
- **`ends-with()`** - заканчивается на
- **`position()`** - позиция

#### Логические операторы:

- **`and, or`** - для комбинированных условий
- **Пример:** `//a[@class = 'link' and contains(text(), 'example')]`

### Примеры XPath локаторов:

#### По атрибутам:

- **`//*[@id='username']`** - по ID
- **`//*[@class='passwords']`** - по имени класса
- **`//*[@name='pass']`** - по имени
- **`//p`** - по имени тега

#### По тексту:

- **`//*[text()='Submit']`** - по тексту

#### С использованием функций:

- **`//*[contains(@href, 'google.com')]`** - использовать Contains
- **`//*[starts-with(@id, 'user')]`** - в начале
- **`//*[ends-with(@id, 'name')]`** - в конце

### CSS селекторы:

#### Основные селекторы:

- **`#my-id`** - по ID
- **`.my-class`** - по классу
- **`[name='q']`** - по атрибуту
- **`button[type='submit']`** - по тегу и атрибуту

### Разница между статическим и динамическим путем:

#### Статический путь:

- **`html/body/div[1]/div[2]`** - жестко привязан к структуре

#### Динамический путь:

- **`//input[contains(@id,'user')]`** - более гибкий поиск

### Общий синтаксис XPath:

**`Путь = // имя_тега [@атрибут = 'значение']`**

#### Примеры:

- **`//input[@id = 'username']`** - по имени тега
- **`//button[contains(@class, 'Submit')]`** - использование contains()
- **`//input[starts-with(@name, 'email')]`** - использование starts-with()
- **`//input[@id='password']/preceding-sibling::label`** - использование preceding-sibling

## 10. Telegram Bot API

### Взаимодействие с пользователем

**Telegram бот взаимодействует с пользователем через Telegram API**

### Механизмы получения сообщений:

#### Long Polling:

- **Бот запрашивает "Есть новые сообщения?"** - просто, но неэффективно

#### Webhook:

- **Бот дает Telegram URL-адрес** - на который Telegram сам отправляет сообщения

### Подключение к API:

1. **Создать бота-сервис в Telegram** (через Bot Father)
2. **Получить токен** (от Bot Father)
3. **Запрос к API должен содержать токен**
4. **Токен проставляется в конфигурациях**

### Особенности работы:

- **Как и в обычном REST API** - в боте сохраняются состояния
- **Важно тестировать полные пути** - учитывая сохранение состояний

## 13. Хранение данных в браузере

### Сравнение механизмов хранения:

| Характеристика   | Cookie                                           | Local Storage                                                                              | Session Storage                           |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------ | ----------------------------------------- |
| **Срок жизни**   | Устанавливается сервером                         | Сохраняются, пока пользователь их не почистит вручную                                      | Действуют до закрытия вкладки браузера    |
| **Доступ**       | Доступны для клиента (браузера) и сервера        | Только для клиента (браузера)                                                              | Только для клиента (браузера)             |
| **Объем данных** | 2-5 КБ                                           | 5-10 МБ                                                                                    | Временное хранение                        |
| **Назначение**   | Аутентификация, персонализация, отслеживание     | Хранение данных, которые должны сохраняться долгое время (например, режим темы интерфейса) | Временное хранение данных                 |
| **Безопасность** | Уязвимости для CSRF (Cross-Site Request Forgery) | Уязвимости для XSS (Cross-Site Scripting)                                                  | Уязвимости для XSS (Cross-Site Scripting) |
| **Пример**       | Токен сессии                                     | Настройка интерфейса                                                                       | Заполненная форма перед отправкой         |

## 14. Linux команды

### Работа с файловой системой:

#### Навигация:

- **`pwd`** - текущая папка
- **`ls`** - вложенные папки
- **`ls -l`** - более детальная информация
- **`ls -R`** - рекурсивно проходить по папкам

#### Перемещение по директориям:

- **`cd <имя папки>`** - открыть папку
- **`cd ..`** - повернуться назад
- **`cd -`** - возвращает в предыдущую папку
- **`dirs -v`** - показывает в каких папках был

#### Работа с файлами:

- **`touch`** - создать файл
- **`rm`** - удалить
- **`rmdir`** - удалить директорию
- **`cp`** - копировать
- **`mv`** - переименование и перемещение файлов

#### Поиск файлов:

- **`find . -name "d*"`** - поиск
- **`sudo find . -type f -name ".*"`** - скрытые файлы находит
- **`rm -rf`** - рекурсивно форс удалить папку со всеми файлами и вложениями

#### Работа с текстом:

- **`echo`** - вывод в консоль
- **`echo "test" >> animal22.json`** - через echo можно записать в файл
- **`nano`** - редактировать файл
- **`cat`** - просмотр файла
- **`vim`** - выйти :wq

#### Анализ файлов:

- **`wc -w animal22.json`** - количество слов
- **`wc -l`** - количество линий
- **`wc -m`** - количество символов
- **`diff`** - сравнение файлов

## 15. HTML основы

### Структура HTML документа:

#### Основные элементы:

- **`<!DOCTYPE html>`** - первый элемент в HTML для задания типа документу
- **`<html>`** - корневой элемент, определяет тип документа
- **`<head>`** - метаданные (заголовок, кодировка, стили, скрипты)
- **`<body>`** - контент страницы

### Основные HTML элементы:

#### Заголовки:

- **`<h1>...<h6>`** - заголовки разного уровня

#### Текстовые элементы:

- **`<p>`** - абзац
- **`<br>`** - перенос строки
- **`<hr>`** - горизонтальная линия

#### Ссылки и изображения:

- **`<a href="URL">TEXT</a>`** - ссылки
- **`<a target="_blank">`** - открыть в новой вкладке
- **`<img src="img.jpg" alt="Описание">`** - изображение с альтернативным текстом

#### Списки:

- **`<ol> <li></li> </ol>`** - нумерованные списки
- **`<ul> <li></li> </ul>`** - маркированные списки

#### Формы:

- **`<form>`** - форма
- **`<input type="text|number|password">`** - поля ввода
- **`<textarea>`** - многострочное поле
- **`<button>`** - кнопка
- **`<label>`** - подпись к полю
- **`<select>`** - выпадающий список
- **`<option>`** - пункт списка
- **`<fieldset>`** - группа полей
- **`<legend>`** - заголовок группы

### Типы элементов:

#### Блочные элементы:

- **`div, p, h1..`** - занимают всю ширину

#### Строчные элементы:

- **`span, a, img`** - занимают только необходимое место

### Семантические элементы:

- **`<header>`** - шапка
- **`<nav>`** - навигация
- **`<section>`** - раздел
- **`<article>`** - самостоятельный блок контента

### Атрибуты:

- **`id, class, style, title, lang`** - основные атрибуты

### Мета-элементы:

- **`<title>`** - заголовок страницы
- **`<link>`** - подключение внешних ресурсов
- **`<script>`** - подключение скриптов

## 16. Моки и стабы в тестировании

### Моки (Mocks)

#### Определение:

- **Полнофункциональные тестовые объекты**
- **Позволяют работать с аргументами и проверками ожиданий**

#### Размещение и запуск:

- **Располагаются на мок-сервере**
- **Хранятся в отдельной папке в репозитории**
- **Могут быть запущены локально или через Docker**

#### Команды запуска:

- **`docker compose up -d mock-service`** - запуск через Docker
- **Могут быть развернуты через CI/CD пайплайн**

#### Архитектура:

- **Мок-сервис поднимается как сайдкар-контейнер** вместе с тестируемым приложением
- **Настройка мок-сервиса возможна через Bash в файле `.env`**

#### Пример конфигурации:

- **`Payment-Service = http://mock-service:8080`**
- **Файлы конфигурации мока рекомендуется размещать рядом с его кодом**

### Стабы (Stubs)

#### Определение:

- **Возвращают заранее подготовленные ответы**
