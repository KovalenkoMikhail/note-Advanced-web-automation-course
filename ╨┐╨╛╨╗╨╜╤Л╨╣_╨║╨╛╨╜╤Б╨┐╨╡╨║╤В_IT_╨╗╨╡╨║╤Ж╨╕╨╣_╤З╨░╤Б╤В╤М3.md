# Полный конспект IT лекций - Часть 3

## 19. Тестирование программного обеспечения

### Тестовый случай (Test Case):

#### Структура тест-кейса:

- **ID** - идентификатор
- **Title** - заголовок
- **Type** - тип
- **Priority** - приоритет
- **Preconditions** - предусловия
- **Steps** - шаги
- **Expected Result** - ожидаемый результат
- **Post conditions** - постусловия

### Определение качества ПО:

**Качество ПО - совокупность характеристик, удовлетворяющих установленные и предполагаемые потребности**

### Этапы тестирования:

1. **Анализ продукта** (Product Analysis)
2. **Работа с требованиями** (Work with requirements)
3. **Тест-план** (Test Plan)
4. **Создание тестовой документации** (Creation of test documentation)
5. **Тестирование** (Testing)
6. **Отчет о тестировании** (Test Report)
7. **Стабилизация** (Stabilization)
8. **Эксплуатация** (Operation/Maintenance)

### Build Verification (Верификация сборки):

#### Типы быстрого тестирования:

- **Smoke** (Смоук) - быстрый тест на стабильность основных функций
- **Sanity** (Санити) - более детальная проверка функционала

### Принципы тестирования:

1. **Тестирование демонстрирует наличие дефектов**
2. **Исчерпывающее тестирование недостижимо**
3. **Раннее тестирование**
4. **Скопление дефектов**
5. **Парадокс пестицида**
6. **Тестирование зависит от контекста**
7. **Заблуждение об отсутствии ошибок**

### Виды тестирования:

#### Функциональные виды тестирования:

- **Functional Testing** - что делает система? Какие функции выполняет?
- **GUI test** - Graphical user interface
- **Security and Access Control Testing**
- **Interoperability test**

#### Нефункциональное тестирование:

- **Performance** (Производительность):
  - **Load test** - много пользователей
  - **Stress** - пиковые значения
  - **Volume** - много данных
- **Stability and Reliability** - стабильность и надежность
- **Installation** - установка
- **Failover and Recovery** - отказоустойчивость и восстановление
- **Usability** - удобство использования
- **Configuration test** - конфигурационное тестирование

#### Связанные с изменениями:

- **Smoke** - дымовое тестирование
- **Regress** - регрессионное тестирование
- **Re-test** - повторное тестирование

#### Другие виды:

- **Exploratory** (исследовательское) - изучение системы, проектирование тест-кейсов на опыте тестера QA
- **Ad-hoc** - тестирование "от балды" (без формальных тест-кейсов)

### Структура отчета об ошибке (Баг-репорт):

#### Основные поля:

- **ID** - идентификатор
- **Title** - описание проблемы
- **Project** - название проекта
- **Component** - затронутый компонент
- **Version** - версия продукта
- **Severity** - степень влияния
- **Priority** - срочность исправления
- **Status** - текущее состояние
- **Author** - кто завел ошибку
- **Assignee** - кто назначен на исправление
- **Env** - среда воспроизведения
- **Build version** - конкретная сборка

#### Детали воспроизведения:

- **Steps to reproduce** - шаги воспроизведения
- **Actual Result** - фактический результат
- **Expected result** - ожидаемый результат

#### Приложения к баг-репорту:

- **Screen shots** - скриншоты
- **Video** - видеозапись
- **Credentials** - учетные данные
- **Browser logs err** - логи браузера, ошибки
- **Server logs** - логи сервера
- **API request** - API запрос
- **Analytics events** - события аналитики
- **Database data** - данные базы данных
- **Database queries** - запросы к базе данных
- **Comments / Notes** - комментарии / заметки
- **Link task** - ссылка на задачу
- **HAR archive** - HAR-архив

### Требования к тестированию:

1. **Корректность**
2. **Недвусмысленность**
3. **Полнота**
4. **Непротиворечивость**
5. **Упорядоченность** (по важности / стабильности)
6. **Проверяемость**
7. **Модифицируемость**
8. **Трассируемость**
9. **Понимаемость**

### Уровни тестирования:

1. **Модульное**
2. **Интеграционное**
3. **Системное**
4. **Приемочное**

### Виды тестирования по способу выполнения:

#### Статическое тестирование:

- **Static test** - без запуска кода

#### Динамическое тестирование:

- **Dynamic test** - с запуском кода

### Тестовый дизайн (Test Design):

#### Техники тест-дизайна:

1. **Equivalence (Эквивалентность)** - на клаве (клавиатуре)

2. **Boundary Value Analysis (Анализ граничных значений)**:

   - **Валидные значения:** 1, 10
   - **Невалидные значения:** 0, 11
   - **Полные границы:**
     - **Валидные:** 1, 2, 9, 10
     - **Невалидные:** 0, 11

3. **Cause / Effect (Причина / следствие)**

4. **Error Guessing (Предугадывание ошибки)**

5. **Pair wise (Попарное тестирование)**:

   - **Тестирование пар комбинаций**
   - **И не всех комбинаций**

6. **Decision table (Таблица решений)**:
   - **Набор условий**
   - **Должен привести к определенному действию / решению**

### Диаграммы и схемы:

#### State transition diagram:

- **Диаграмма состояний-переходов**
- **Описание поведения систем**
- **Система имеет конечное число состояний и переходов между ними**
- **Может быть переведена в Decision Table**

#### Use case:

- **Кто?**
- **Что хочет делать?**
- **Шаги**
- **Реакция системы**

#### Block scheme:

- **Для проектирования тестов и наглядности**

### Подходы к тестированию:

- **Semi Exhaustive Test** - в билдинге или подобном
- **Разговорчики driven** - обсуждения
- **Аналитика driven** - аналитика
- **Bugs driven** - баги

### 10 заповедей QA:

1. **Не доверяй разрабу, у меня работает**
2. **Тест-кейсы пиши как будто завтра забудешь**
3. **Проверяй не только то, что должно работать (Happy Path), а и то, что должно сломаться**
4. **Спрашивай. Всегда. Обо всем. Даже если думаешь, что знаешь**
5. **Ты не мешаешь релизу - ты спасаешь компанию**
6. **Незадокументированный баг - легенда, а не факт**
7. **Автотесты могут помочь, но не делают все за тебя**
8. **Никогда не тестируй теми же данными что и разраб**
9. **Чем меньше коммуникаций в команде - тем больше проблем на релизе**
10. **Никогда не верь словам "Мы проверили"**

## 20. Уникальные идентификаторы

### UUID (Universally Unique Identifier)

#### Определение:

- **128-битное число, состоящее из 32 символов**
- **Схема:** 8-4-4-4-12 (стандартный формат с дефисами)

#### Типы UUID:

- **Time-based (Основанный на времени)** - содержит метку времени (timestamp) и MAC-адрес
- **Random-based (Основанный на случайности)** - содержит абсолютно случайные значения
- **Name-based (Основанный на имени)** - генерируется из имени URL или DNS

### ULID (Universally Unique Lexicographically Sortable Identifier)

#### Определение:

- **Универсальный уникальный лексикографически сортируемый идентификатор**
- **Структура:** состоит из 26 символов в кодировке Base 32

#### Компоненты:

- **Timestamp (Метка времени):** 48 бит, первые 10 символов
  - **Измеряется в микросекундах** - обеспечивает сортируемость
- **Randomness (Случайность):** 80 бит, следующие 16 символов являются случайными

#### Свойства:

- **Сортируемость** (компактность)
- **Индексируемость**

## 21. OSI модель

### 7 уровней модели OSI:

| Уровень | Название                             | Протоколы/Функции                                   |
| ------- | ------------------------------------ | --------------------------------------------------- |
| **7**   | **Application (Прикладной)**         | HTTP, FTP, SMTP                                     |
| **6**   | **Presentation (Представительский)** | TLS, SSL                                            |
| **5**   | **Session (Сеансовый)**              | Sockets (передает данные)                           |
| **4**   | **Transport (Транспортный)**         | TCP, UDP (передает сегменты и дейтаграммы)          |
| **3**   | **Network (Сетевой)**                | IP, ICMP, IPsec (передает пакеты)                   |
| **2**   | **Data link (Канальный)**            | Ethernet, Wi-Fi (между одной сетью передает frames) |
| **1**   | **Physical (Физический)**            | Fiber (передает биты через кабели, сетевые карты)   |

## 22. Docker - контейнеризация

### Основные команды Docker:

#### Управление контейнерами:

- **`docker start`** - запустить контейнер
- **`docker stop`** - остановить контейнер
- **`docker restart`** - перезапустить контейнер

#### Выполнение команд:

- **`docker exec -it [имя_контейнера] [команда]`** - выполнение команд внутри контейнера

#### Просмотр контейнеров:

- **`docker ps`** - просмотр запущенных контейнеров

#### Создание и запуск:

- **`docker run -d -it ubuntu`** - создать контейнер и вернуть его ID
  - **`-d`** - detached mode (фоновый режим)
  - **`-it`** - interactive и pseudo-TTY
  - **`ubuntu`** - имя образа

### Docker Run команды:

#### Основные параметры:

- **`docker run`** - запустить контейнер
- **`--name my-nginx`** - дать имя
- **`-P 8880:80`** - пробросить порт 80 изнутри контейнера на порт 8080 на ПК
- **`-d`** - запуск в фоновом режиме

#### Управление контейнерами:

- **`docker stop my-nginx`** - остановить контейнер
- **`docker rm my-nginx`** - удалить контейнер

### Образы и контейнеры:

#### Image (Образ):

- **Шаблон для приложения, фактически контейнер**
- **Архив, когда запускается становится контейнером**

#### Container (Контейнер):

- **Может быть с любым приложением**
- **Rabbit, БА (хоть 10 БА запускай)**
- **В контейнере работает база на каком-то порту**

#### Expose команда:

- **Можно expose какую-то базу**
- **`EXPOSE 5000`** - отдает порт по которому будет подключаться

### Особенности Docker:

- **Контейнеры в основном запускаются локально**
- **Возможно подключение удаленно**
- **Можно запускать несколько контейнеров одновременно на разных портах**

## 23. Базы данных

### SQL vs NoSQL

#### Реляционные базы данных (SQL):

##### Где использовать:

- **Где важна структура**
- **Строгая целостность**

##### Характеристики:

- **Жесткая реляционная структура**
- **Стандартизованный язык**
- **Таблицы с фиксированными колонками**
- **По ACID модели**

##### Масштабирование:

- **Вертикальное** - для увеличения производительности нужен более мощный сервер

##### Транзакции и целостность:

- **Надежные, гарантируют ACID свойства:**
  - **A**tomicity (Атомарность)
  - **C**onsistency (Согласованность)
  - **I**solation (Изолированность)
  - **D**urability (Надежность)

#### NoSQL базы данных:

##### Где использовать:

- **Для больших объемов**
- **Неструктурированных данных**

##### Характеристики:

- **Гибкая безсхемная не реляционная**
- **Разные языки под каждое приложение**
- **Документы пары-ключ значения**
- **По BASE принципам**

##### Применение:

- **Веб/мобильные приложения**
- **Big Data**
- **Кэширование**
- **Realtime analytics**

##### Масштабирование:

- **Горизонтальное** - можно добавлять дополнительные серверы в кластер

##### Транзакции и целостность:

- **Придерживаются BASE принципов:**
  - **B**asically **A**vailable (Базовая доступность)
  - **S**oft **S**tate (Мягкое состояние)
  - **E**ventually **C**onsistent (Конечная согласованность)

### MongoDB - NoSQL операции

#### Поиск по ID:

```javascript
db.users.find({ _id: new ObjectId('29574/3') });
```

#### Join с использованием $lookup:

```javascript
db.authors.aggregate([
  {
    $lookup: {
      from: 'posts',
      localField: '_id',
      foreignField: 'authorId',
      as: 'post',
    },
  },
]);
```

#### Операторы сравнения:

- **`$eq`** = равно
- **`$ne`** != не равно
- **`$gte`** >= больше или равно
- **`$lte`** <= меньше или равно
- **`$gt`** > больше
- **`$lt`** < меньше

#### Логические операторы:

- **`$and`** (И)
- **`$or`** (ИЛИ)
- **`$not`** (НЕ)
- **`$nor`** (НЕ ИЛИ)

#### Пример запроса:

```javascript
{
  $tags: {
    $in: ['Vasya'];
  }
}
```
